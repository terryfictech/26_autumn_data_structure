# 实验 1：LRU 缓存模拟器

程序写在 `lab1.c` 中，提供顺序表和带头结点的单链表两种实现。启动时默认使用顺序表，缓存容量为 3。

## 运行程序

在 `lab1` 目录打开 PowerShell，执行：

```powershell
C:\mingw64\bin\gcc.exe -std=c11 -Wall -Wextra lab1.c -o lab1.exe
.\lab1.exe
```

修改源码后，重新执行第一行编译命令，`lab1.exe` 才会更新。

## 菜单说明

| 选项 | 用途 |
| --- | --- |
| 1 | 选择顺序表或单链表，清空缓存和统计。 |
| 2 | 设置容量，清空缓存和统计。 |
| 3 | `GET`：按提示输入 key。 |
| 4 | `PUT`：按提示输入 key 和 value。 |
| 5 | 查看当前缓存。 |
| 6 | 查看统计。 |
| 7 | 读取文件，在当前缓存上执行操作。 |
| 8 | 随机生成操作，在当前缓存上执行。 |
| 9 | 用同一文件对比两种实现；两边都从空缓存开始。 |
| 10 | 随机生成一组操作，对比两种实现；两边都从空缓存开始。 |
| 11 | 开关每步操作后的缓存输出。大量测试时建议关闭。 |
| 12 | 用题目给的页面访问序列计算命中率。 |
| 0 | 退出程序。 |

## 操作文件

每行写一条操作，可以留空行，也可以用 `#` 写注释。例如，把下面内容保存为 `ops.txt`：

```text
PUT 1 1
PUT 2 2
GET 1
PUT 3 3
GET 2
```

先用菜单 2 把容量设为 2，再打开菜单 11 的逐步输出，用菜单 7 运行 `ops.txt`。最后一次 `GET 2` 应显示未命中。要比较两种实现，选菜单 9 并输入同一个文件名。手动操作时直接选菜单 3 或 4，不需要输入整行命令。

## 看懂结果

缓存按“最近使用 → 最久未使用”输出；插入新 key 且缓存已满时，淘汰最后一个。命中率只统计 `GET`，不统计 `PUT`。未命中显示 `-1`；若存储的 value 本身是 `-1`，输出仍会标明它是命中。

性能对比的计时不包括读文件和打印结果。操作太少时耗时容易波动，可用菜单 10 测试一万次操作。
