# 数据结构实验 1：LRU 缓存模拟器

本项目使用 **C 语言**完成。全部程序在 `lab1.c` 中：顺序表和带头结点的单链表各实现一遍 LRU。`实验1.docx` 是老师提供的实验说明。

## 编译和运行

你已有的编译器是 `C:\mingw64\bin\gcc.exe`，不需要安装新环境。在本目录打开 PowerShell，运行：

```powershell
New-Item -ItemType Directory -Force build
C:\mingw64\bin\gcc.exe -std=c11 -O2 -Wall -Wextra lab1.c -o build\lab1.exe
.\build\lab1.exe
```

修改 `lab1.c` 后，要重新执行第二行编译命令，exe 才会更新。上级 VS Code 的默认任务使用 `g++`，是编译 C++ 活动文件的任务；做本实验请用上面的 `gcc` 命令。

也可以在项目目录运行 `build.bat`：它执行同一条 GCC 编译命令，作为本项目的简易构建文件。

## 程序如何使用

程序启动后显示菜单。默认容量为 3，采用顺序表。可以切换到单链表、修改容量、手动执行 `GET/PUT`、查看缓存状态和统计，也可以导入文件或随机生成操作。切换实现或容量会重新建立空缓存。

操作文件每行一条指令，允许空行和 `#` 注释，例如：

```text
PUT 1 100
GET 1
PUT 2 200
```

`tests/sample_ops.txt` 是现成的示例文件。用菜单 9 可以把同一文件交给两种实现比较；菜单 10 可以生成一组随机操作并比较。两种实现各自从空缓存开始。计时不包含文件读取和屏幕打印；小规模测试的时间容易波动，请用较多操作进行性能分析。

普通缓存的命中率只统计 `GET`，`PUT` 不计入。插入新 key 且缓存已满时才增加淘汰次数。内部用“是否命中”和输出参数分别表示查找结果，因此 `value=-1` 可以正常存储。菜单 12 的页面实验把每一次页面访问都计入命中率，未命中后才插入页面。

`build/lab1.exe` 是编译得到的运行文件，删除后可以重新编译生成。实验报告暂未编写。
